__App Overview__

The sunflower app is a sample application used to demonstrate some best practices in Android development, particularly the use of modern architecture components to create a gardening application. The primary functionalities of this app incluyde browsing a list of plants, adding a plant to a user's garden, and viewing detailed information about individual plants. The app's overall architecture is based on the Model-View-ViewModel (MVVM) architecture pattern. The Model (data) layer utilizes Room for a local data persistence and defines two entities, Plant and GardenPlanting. The Plant entity contains information about various different plants, and the GardenPlanting entity establishes the relationship between plants and a user's garden. The PlantDao and GardenPlantingDao are Data Access OBjects (DAOs) for interacting with the Plant and GardenPlanting entities. The PlantRepository and GardenPlantingRepository are data access points and abstract the data layer from the rest of the application. The View (UI) layer is built using Compose, Android's modern UI toolkit, which allows for declarative UI programming and overall simplifies the creation of the UI for this app. Each screen has a corresponding screen file in the compose directory. The files in the ViewModel directory act as a bridge between the View and Model layers. These ViewModels use Flow to expose data to the UI and handle any user interactions. Dependency injections is handled by Hilt, which simplifies the creation and management of any ViewModel and Repository instances. 

__Key Feature 1: Displaying Plant List__

The first key feature to highlight is the display of the available plant list. To highlight the high-level functionality of this feature, the user is presented with a scrollable list of available plants and allows them to browse and select plants for further information. This functionality is implemented in two main files, PlantListScreen.kt and PlantListViewModel.kt. 

PlantListScreen.kt represents the View (UI) layer of this component. This file implements the PlantListScreen composable, which defines the UI using a LazyVerticalGrid to render the list of plants in two columns. The LazyVerticalGrid is configured with imePadding() to handle any padding necessary when the on-screen keyboard is enabled, and contentPadding to add spacing around the grid. The items() function in LazyVerticalGrid iterates through each plant that is passed in through PlantListViewModel. For each plant it renders a PlantListItem composable that is responsible for displaying the plant's image and name. Each plant inside of the LazyVerticalGrid is clickable, and when it is it calls onPlantClick. This function takes in the plant as a parameter and triggers navigation to the plant detail screen, which holds more information about the selected plant. 

PlantListViewModel.kt represents the ViewModel layer, which acts as the middle-man between the UI (View) and data (Model) layers. This file implements PlantListViewModel, which uses Hilt to inject PlantRepository and SavedStateHandle. The PlantListViewModel manages the data required for the PlantListScreen on the front end. It initializes a MutableStateFlow, which it names growZone, which represents the current grow zone filter. The initial value for growZone is retrieved from the SavedStateHandlw through GROW_ZONE_SAVED_STATE_KEY. If this is not found, it defaults to NO_GROW_ZONE, or -1. The plants LiveData provides the list of plants to the UI, and is derived from a flatMapLatest operation on growZone. This ensures that whenever the growZone value changes a new query is triggered to PlantRepository, ensuring that the plant list is always the most up to date. If the growZone value is NO_GROW_ZONE, plantRepository.getPlants() is called to get all plants, otherwise plantRepository.getPlantsWithGrowZoneNumber(zone) is called to fetch plants in a specific grow zone. The PlantRepository then gets the correct plant data from PlantDao.kt which performs the database queries through Room. The ViewModel also uses viewModelScope.launch to get changes from growZone and update SavedStateHandle with the new value of growZone, which ensures that the filter selection is maintained. PlantListViewModel uses methods like updateData(), setGrowZoneNumber(), clearGrowZoneNumber(), and isFiltered() for the UI to interact with and modify the grow zone filter. 

This component interacts with the Model, or data, layer through PlantListViewModel.kt. This file interacts with the PlantRepository.kt, which has functions for retrieving plant data from the database. The PlantRepository works with the Room database through the PlantDao.kt to perform these operations. 

__Key Feature 2: Adding Plant to Garden__

The second key feature to highlight is the ability to add a plant to the user's garden. To overview the high-level functionality of this feature, the user can select a plant from the plant detail screen and add it to their garden by clicking the "+" button seen in the front end UI. This functionality is implemented in two main files, PlantDetailView.kt and PlantDetailViewModel.kt. 

PlantDetailView.kt represents the View, or UI, layer of this component. This file implements the PlantDetailsScreen composable which displays detailed information for a selected plant. It receives several callbacks for handling user interactions including adding to the garden, navigating back, sharing, and viewing the gallery. PlantDetailsScreen also observes LiveData and StateFlow from PlantDetailViewModel to render relevant plant details like the image, name, watering interval, and description. PlantDetailsScreen manages the layout thorugh a scrollable Column to display relevant information. It includes a ConstraintLayout to position the plant's image, the add to garden button, and the plant's information section. The PlantImage composable uses GlideImage to load and display the plant's image through a URL, and PlantInformatoin displays the plant's name, watering interval, and description. If a plant is not already in the user's garden, a PlantFab composable is displayed. This composable contains a Floating Action Button (FAB), which when clicked triggers onFabClick which in turn calls addPlantToGarden() in PlantDetailViewModel.kt. The PlantDetailsScreen composable also uses showSnackbar LiveData from PlantDetailViewModel. If this is true it displays a snackbar message using TextSnackbarContainer composable which indicates that the plant has been added to the garden. onDismissSnackbar is used to reset the showSnackbar LiveData in PlantDetailViewModel. The composable also includes PlantToolbar, which includes the top app bar with the plant's name and navigtation actions. 

PlantDetailViewModel.kt acts as the ViewModel layer of this component, which coordinates the state and logic for the plant details feature. It begins by extracting the plantId from SavedStateHandle, which ensures that the correct plant's data is retrieved. This plantId is then utilized to fetch the correct plant object from PlantRepository as a LiveData object. The ViewModel leverages the GardenPlantingRepository to manage garden plantings throuhg addPlantToGarden(), which initiates a coroutine in viewModelScope to call gardenPlantingRepository.createGardenPlanting(plantId) which puts a new GardenPlanting entry in the database. The isPlanted property, which is a StateFlow, shows whether the plant has already been added to the user's garden. isPlanted is implemented using gardentPlantingRepository.isPlanted(plantId).stateIn(...) with SharingStarted.WhileSubscribed(5000) to ensure that the value is updated while there are subscribers. To provide user feedback this ViewModel uses MutableLiveData for the showSnackbar state. Upon adding a plant to the garden, _showSnackbar.value is set to true which triggers the UI to display a snackbar message. dismissSnackbar() then resets this state to false to get rid ofthe snackbar. hasValidUnsplashKey() checks the validity of the Unsplash API access key, which is used to populate images into the UI. This function returns true if the key is not null, which shows that the app can access the Unsplash API for the gallery. 

This component interacts with the Model, or data, layer through PlantDetailViewModel.kt. This file interacts with GardenPlantingRepository.kt, which has functions for saving garden planting data to the database. The GardenPlantingRepository interacts with GardenPlantingDao.kt to perform database operations, like inserting GardenPlanting objects into the Room database.
